# Setup Guide — O/L LMS with Parental Monitoring

This guide walks you through installing and running the application from a clean
machine. No prior knowledge of the codebase is assumed. Follow the steps in
order; each one takes only a few minutes.

If you only want to *run* what's already deployed, skip to
[7. First login & guided tour](#7-first-login--guided-tour).

---

## What this system is

An Online O/L (Ordinary Level) Learning Management System with a **parental
monitoring** layer. It has three roles:

| Role | What they do |
|------|--------------|
| **Admin** | Creates all accounts, uploads learning materials, builds & grades quizzes, uploads report cards, runs performance predictions. |
| **Parent** | Monitors their linked child's activity, engagement and quiz results; opts into camera-based attention verification; views report cards & notifications. |
| **Child** | Studies materials and takes quizzes. |

There is **no public sign-up** — every account is created by an admin. This is a
deliberate safety choice for a platform involving minors.

### Technology

- **Frontend:** React 19 + TypeScript + Vite + Tailwind CSS
- **Backend:** FastAPI (Python)
- **Database, Auth & File Storage:** Supabase (hosted PostgreSQL)
- **Machine learning:** scikit-learn (a Random Forest risk predictor, trained offline)

## 1. Prerequisites

Install these first:

| Tool | Version | Check with |
|------|---------|-----------|
| **Node.js** | 20 LTS or newer (22 LTS recommended) | `node -v` |
| **Python** | 3.11 or 3.12 | `python --version` |
| **Git** | any recent | `git --version` |
| **A Supabase account** | free tier is fine | [supabase.com](https://supabase.com) |

You do **not** need to install PostgreSQL locally — Supabase hosts it.

---

## 2. Create the Supabase project & database

1. Go to [app.supabase.com](https://app.supabase.com) → **New project**. Choose
   a name and a strong database password, and wait ~2 minutes for it to
   provision.
2. Open the **SQL Editor** → **New query**.
3. Open the file `app/supabase/schema.sql` from this project, copy **all** of
   its contents, paste into the editor, and click **Run**.
   - This creates every table, type, and security policy the app needs. It is a
     complete fresh-install script — you do **not** need to run the files in
     `app/supabase/migrations/` (those are only for upgrading an already-running
     older database).

> ✅ You now have an empty but fully-structured database.

---

## 3. Create the two storage buckets

The app stores uploaded files (learning materials, report-card PDFs) in Supabase
Storage. Create these **manually** — bucket creation from SQL is unreliable on
some projects.

In the Supabase dashboard → **Storage** → **New bucket**, create **both**:

| Bucket name | Public? |
|-------------|---------|
| `materials` | **OFF** (private) |
| `report-cards` | **OFF** (private) |

Both must be **private** — files are served only through signed, time-limited
URLs generated by the backend.

---

## 4. Collect your Supabase keys

In the dashboard → **Project Settings** → **API**, note these four values:

| Value on the page | Used as |
|-------------------|---------|
| **Project URL** | `SUPABASE_URL` and `VITE_SUPABASE_URL` |
| **anon / public** key | `VITE_SUPABASE_ANON_KEY` |
| **service_role** key | `SUPABASE_SERVICE_ROLE_KEY` (⚠️ secret — backend only) |
| **JWT Secret** (under *JWT Settings*) | `SUPABASE_JWT_SECRET` |

> ⚠️ The **service_role** key bypasses all security rules. Keep it on the
> backend only. Never put it in the frontend or commit it to Git.

## 5. Backend setup (FastAPI)

Open a terminal and move into the backend folder. **All commands in this section
are run from `app/backend`.**

```bash
cd app/backend
```

### 5.1 Create and activate a virtual environment

A "virtual environment" (venv) keeps this project's Python packages isolated from
the rest of your system. Create it once:

```bash
python -m venv .venv
```

Then **activate** it. You must do this every time you open a new terminal to work
on the backend — you'll know it's active because your prompt shows `(.venv)`.

```bash
# Windows (PowerShell):
.venv\Scripts\Activate.ps1

# Windows (Command Prompt):
.venv\Scripts\activate.bat

# macOS / Linux:
source .venv/bin/activate
```

> **Windows note:** if PowerShell says *"running scripts is disabled on this
> system"*, run this once, then activate again:
> `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned`

### 5.2 Install the dependencies

With the venv active, upgrade pip and install everything the backend needs:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

This installs (from `requirements.txt`):

| Package | Purpose |
|---------|---------|
| `fastapi`, `uvicorn[standard]` | The web API framework and the server that runs it |
| `pydantic-settings` | Loads and validates the `.env` configuration |
| `email-validator` | Validates email addresses on account creation |
| `supabase` | Talks to the Supabase database, auth, and storage |
| `pyjwt`, `cryptography` | Verifies login tokens securely |
| `python-multipart` | Handles file uploads (materials, report cards) |
| `scikit-learn`, `pandas`, `numpy`, `joblib` | The machine-learning risk predictor |
| `pytest`, `httpx` | Running the automated tests (development only) |

The ML packages (`scikit-learn`, `pandas`, `numpy`) are the largest, so the first
install may take a few minutes.

### 5.3 Create the environment file

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Open `app/backend/.env` and fill in the values from [step 4](#4-collect-your-supabase-keys):

```env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
SUPABASE_JWT_SECRET=your-jwt-secret
CORS_ORIGINS=http://localhost:5173
```

All four values are required — the backend refuses to start if any are missing.

### 5.4 Start the backend

```bash
uvicorn app.main:app --reload --port 8000
```

Leave this terminal running. You should see `Application startup complete`. The
API is now at `http://localhost:8000`.

**Verify it works:** open `http://localhost:8000/docs` in a browser — you should
see the interactive API documentation page. (`--reload` auto-restarts the server
whenever you edit backend code; drop it in production.)

## 6. Frontend setup (React)

Open a **second** terminal in the `app/frontend` folder:

```bash
# 1. Install dependencies
npm install

# 2. Create the environment file
cp .env.example .env      # Windows: copy .env.example .env
```

Open `app/frontend/.env` and fill in:

```env
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
VITE_API_URL=http://localhost:8000
```

Start the frontend:

```bash
npm run dev
```

The app is now at **http://localhost:5173**.

## 7. Create the first admin account

There is no sign-up screen, so bootstrap the first admin from the command line.
With the **backend virtual environment active** and its `.env` filled in, run
from `app/backend`:

```bash
python scripts/create_admin.py admin@example.com "StrongPassword123" "Site Admin"
```

You can now log in at **http://localhost:5173** with that email and password.

## 8. First login & guided tour

Once logged in as the admin, a typical setup flow is:

1. **Create accounts** — in the Admin Console, add parent and child accounts,
   then **link** each parent to their child.
2. **Add a subject** and **upload materials** (documents, videos, exam papers,
   slides).
3. **Build a quiz** with multiple-choice and/or short-answer questions.
4. **Log in as the child** (in a separate browser/incognito window) to browse
   materials and take the quiz.
5. **Log in as the parent** to see the child's activity, monitor a session
   (optionally with camera attention), and view results & notifications.
6. **Grade short answers** — back as admin, open the quiz's **Results**, and use
   **Grade** on any attempt marked *Needs grading*. The parent is notified once
   grading is complete.
7. **Run predictions** — in the admin **Risk Predictions** section, click **Run
   predictions** to populate each student's risk band.

### Optional: load demo data

To explore the app with realistic pre-filled data instead of starting empty,
run from `app/backend` (venv active):

```bash
python -m app.scripts.seed_demo          # add demo accounts, activity, quizzes
python -m app.scripts.seed_demo --clear  # remove all demo data again
```

## 10. Troubleshooting

| Symptom | Cause & fix |
|---------|-------------|
| **"Missing VITE_SUPABASE_URL…"** on load | The frontend `.env` isn't filled in, or you didn't restart `npm run dev` after editing it. |
| **Login fails / 401** | Check `SUPABASE_JWT_SECRET` and `SUPABASE_URL` in the backend `.env` are correct and the backend was restarted. |
| **CORS / "blocked" errors in the browser console** | Make sure the backend is running and `CORS_ORIGINS` in the backend `.env` matches the frontend URL (`http://localhost:5173`). |
| **File upload/download says "File is missing from storage"** | The `materials` / `report-cards` buckets weren't created (step 3), or were created public. Recreate them as **private**. |
| **Empty risk roster** | Predictions haven't been run yet — click **Run predictions** in the admin Risk Predictions section. |
| **Camera attention not starting** | It requires the parent to grant camera permission and needs `https` or `localhost` (browsers block camera on plain-http remote hosts). |

## 11. Deploying to production (overview)

For a live deployment (beyond local development):

1. **Database & storage** already live on Supabase — no change needed.
2. **Backend** — host the FastAPI app (e.g. Render, Railway, Fly.io, or any
   container host; a `Dockerfile` is included in `app/backend`). Set the same
   four environment variables there, and set `CORS_ORIGINS` to your real
   frontend domain.
3. **Frontend** — run `npm run build` and deploy the static `dist/` output
   (e.g. Vercel, Netlify, Cloudflare Pages). Set the three `VITE_*` variables to
   production values, with `VITE_API_URL` pointing at the deployed backend.
4. Serve everything over **HTTPS** (required for the camera feature).

## 12. Important notes for evaluation

A few honest boundaries worth knowing (full detail in `app/README.md`):

- **The risk predictor is trained on simulated data**, generated in the app's
  own feature schema and grounded in public education datasets. Its accuracy and
  explanations reflect those simulated relationships — framed as *association,
  not causation*. Real deployment would require retraining on real, consented
  student data.
- **Camera attention** is an *indicative* signal. All video processing happens
  in the browser; **only computed numbers are sent to the server, never video or
  images**.
- **Parental Engagement Index** is a transparent weighted formula (not machine
  learning), chosen for explainability.
